Minimal site小站 / 原型

Plain PHP templates, no database.纯 PHP 模板，没有数据库。

5 direct直接依赖 Runnable starter可运行骨架 
composer require migears/web migears/template migears/log migears/debug migears/http-exceptions

Install directly直接安装

migears/web migears/template migears/log migears/debug migears/http-exceptions

Add only when needed按需添加

migears/captcha migears/mail

Use when适用

  • You need server-rendered pages and prefer plain PHP templates.
  • You have no data layer yet.
  • 需要服务端渲染页面，并偏好纯 PHP 模板。
  • 暂时没有数据层。

Avoid when不适用

  • Page structure is highly repetitive or edited by non-PHP users; use content-site.
  • You need an API only; use rest-api.
  • 页面结构高度重复或由非 PHP 人员维护；改用 content-site。
  • 只需要 API；改用 rest-api。

Remove if可以去掉

  • debug in production.
  • log if you truly need no logging; register a NullLogger instead.
  • 生产环境去掉 debug。
  • 完全不需要日志时去掉 log，改为注册 NullLogger。

Notes备注

  • The starter runs against the current 2.3 tree. The public repositories may lag until the current test round is released.
  • starter 运行在当前 2.3 代码树上。当前测试轮发布前，公开仓库可能滞后。

Page front-end页面前端

migears/yaml-pages migears/xml-pages migears/pages

Pick one by preference. The module list and composer command use yaml-pages as the example; swap it for xml-pages or pages.按喜好任选其一。模块清单与 composer 命令以 yaml-pages 为例；可替换为 xml-pages 或 pages。

Use when适用

  • Lists, forms, and detail pages repeat across the application.
  • You want declarative page definitions instead of writing every template by hand.
  • 列表、表单与详情页在应用里反复出现。
  • 希望使用声明式页面定义，而不是手写每一个模板。

Avoid when不适用

  • You prefer plain PHP templates, even for a larger site; use minimal-site.
  • You only need JSON; use rest-api.
  • 即使页面较多，你仍偏好纯 PHP 模板；改用 minimal-site。
  • 只需要 JSON；改用 rest-api。

Remove if可以去掉

  • security when there is no login or CSRF surface.
  • validator when every form is trivial.
  • 没有登录或 CSRF 面时去掉 security。
  • 所有表单都很简单时去掉 validator。

Notes备注

  • yaml-pages and xml-pages pull in pages; pages pulls in template.
  • Pick the page front-end by preference: pages (array DSL), yaml-pages, or xml-pages.
  • Add i18n only when there is a second language.
  • yaml-pages 与 xml-pages 会带入 pages；pages 会带入 template。
  • 页面前端按喜好选择：pages（数组 DSL）、yaml-pages 或 xml-pages。
  • 只有存在第二语言时才添加 i18n。

Use when适用

  • The backend serves JSON only.
  • One table maps to one domain object for most endpoints.
  • 后端只提供 JSON。
  • 大多数端点是一张表对应一个领域对象。

Avoid when不适用

  • You need server-rendered pages; use minimal-site or content-site.
  • You need an ORM with identity mapping and lazy relations.
  • 需要服务端渲染页面；改用 minimal-site 或 content-site。
  • 需要带身份映射与懒加载关系的 ORM。

Remove if可以去掉

  • cache when nothing is actually cached; dao still pulls it in, but you can ignore it.
  • debug in production.
  • 没有实际缓存时可以不关心 cache；dao 仍会带入它。
  • 生产环境去掉 debug。

Notes备注

  • dao pulls in sql, domain, cache, and utils.
  • Add manager only for multi-step use cases or events.
  • Use sql directly for joins and reports.
  • dao 会带入 sql、domain、cache 与 utils。
  • 只有多步骤用例或事件时才添加 manager。
  • 连接与报表直接使用 sql。

Add only when needed按需添加

migears/acl-featurepending待发布 migears/web-guardspending待发布 migears/rpc migears/jobs migears/mail migears/ai-proxy

Use when适用

  • Native mobile or desktop clients need long-lived login.
  • You want bearer tokens with rotating refresh tokens.
  • 原生移动端或桌面客户端需要长期登录。
  • 需要 Bearer token 与刷新令牌轮换。

Avoid when不适用

  • Browser session login; use content-site with migears/security.
  • Simple static API keys with no refresh lifecycle.
  • 浏览器会话登录；改用 content-site 搭配 migears/security。
  • 只需静态 API key，没有刷新生命周期。

Remove if可以去掉

  • security-token-auth for public read-only endpoints.
  • debug in production.
  • 公开只读端点可以去掉 security-token-auth。
  • 生产环境去掉 debug。

Notes备注

  • acl-feature and web-guards are optional access layers; add them only when a static endpoint matrix or cross-cutting guards are needed.
  • rpc only when clients actually speak JSON-RPC.
  • acl-feature 与 web-guards 是可选访问层；只有需要静态端点矩阵或统一守卫时才添加。
  • 只有客户端确实使用 JSON-RPC 时才添加 rpc。
