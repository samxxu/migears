Do not start from a module list. Start from what the project serves and who maintains it. 不要从模块清单开始，从项目输出什么、由谁维护开始。

01

Does the project serve HTML?项目输出 HTML 吗？

JSON only means no view layer at all. Server-rendered pages mean you need a template engine. 只输出 JSON 就不需要视图层；服务端渲染页面则需要模板引擎。

No, JSON only → REST API否，只输出 JSON → REST API Yes → next question是 → 下一个问题

02

Are pages structurally repetitive?页面结构重复吗？

Page count is a weak signal. Repetition and who edits the page matter more. 页数不是好判据。结构重复度与页面由谁编辑更重要。

No → Minimal site否 → 小站 Yes → Content site是 → 内容站

03

Do native clients need login?原生客户端需要登录吗？

Native apps need bearer tokens and refresh rotation, not browser sessions. 原生应用需要 Bearer token 与刷新轮换，而不是浏览器会话。

No → REST API否 → REST API Yes → Mobile API是 → 移动端 API

Declarative pages are optional. If you want them, pick pages (array DSL), yaml-pages, or xml-pages by preference. Plain template is always valid, including for a small site. 声明式页面不是必需。想用时，按喜好选择 pages（数组 DSL）、yaml-pages 或 xml-pages；纯 template 始终有效，页面少时也一样。

Hard rules硬规则

These are not preferences. They are the mistakes the metadata is meant to prevent. 这些不是偏好，而是元数据要防住的错误。

  • Never install all 30 modules. Start from a recipe and add only when use_when matches.绝不安装全部 30 个模块。从组合起步，只在 use_when 命中时添加。
  • All three page front-ends are valid. pages is the array DSL; yaml-pages and xml-pages are file formats. Pick by preference, not by project size.三种页面前端都可用。pages 是数组 DSL；yaml-pages 与 xml-pages 是文件格式。按喜好选择，而不是按项目大小。
  • Never enable migears/debug in production.绝不要在生产环境启用 migears/debug。
  • migears/jobs is fire-and-forget. If the task needs retries, scheduling, or at-least-once delivery, choose a real queue.migears/jobs 是发射后不管。任务需要重试、调度或至少一次投递时，应选择真正的队列。
  • migears/dao is single-table. Use migears/sql directly for joins, reports, and multi-table aggregates.migears/dao 面向单表。连接、报表与多表聚合应直接使用 migears/sql。
